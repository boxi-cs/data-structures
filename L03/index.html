Linear Data StructuresData Structures · Chapter 3

Three ways of arranging items in a line, each defined by which items you are allowed to reach: a stack gives back the most recent one, a queue the oldest, a deque either end. The restriction is a promise, and the promise is what lets every operation take constant time. We build each one twice, in an array and in a chain of nodes, and then use them on two classic problems: checking brackets and visiting a network nearest-first.

Which end?

The same row of five items (A…E) is handed out three ways: a stack returns E, D, C, B, A; a queue returns A, B, C, D, E; a deque lets you choose the end at every step. The order of the returned items is printed under each.

Why this matters

about 90–120 minutes (4 videos of about 8 minutes plus the exercises).

A smaller promise is easier to keep

Because a stack only ever touches its top, push and pop take constant time however many items it holds; restricting access is a design decision, not a weakness.

Arrays and chains are two answers to the same question

Every structure here can be built on a growing array or on linked nodes, and the trade (copying now and then versus a pointer per item) comes back in every later chapter.

These three show up inside everything else

The call stack that runs your recursion, the queue behind breadth-first search, the deque behind sliding windows: you will meet them again in Chapters 4 and 9.

§1Last in, first out

You press Back and land on the page you were on a moment ago; press it again and you go one page further back. Undo works the same way. Both remember a history and give it back most recent first. A stack is the simplest structure that does exactly that: you may add an item on top (push), look at the top item (top) and remove the top item (pop), and nothing else. The call stack of your program is a stack too: every call pushes a frame, every return pops one.

A stack in an array

A vertical array with a top pointer. Push 3, 7, 1, 9, 4 into a stack that starts with capacity 2: the pile grows, and when it is full a bigger array appears next to it and the items are copied across (a counter shows 2, then 4 copies). Pop returns the items in the opposite order, and popping an empty stack shows the error.

PREDICT

You push 3, then 7, then 1 on an empty stack and pop three times. In what order do the numbers come back?

Show the answer

1, 7, 3: exactly reversed. That reversal is the whole point of a stack, and the reason it is good at undoing things.

§2The operations and what they cost

operationwhat it doescost
push(e)add e on topO(1) (amortized for the array version)
pop()remove and return the top; an error if the stack is emptyO(1)
top()return the top without removing it; an error if emptyO(1)
size() / is_empty()how many items / are there noneO(1)

Push, pop and top only touch the top item and never look at the others, so none of them depends on how many items the stack holds.

NOTE · "A list can do all this and more, so why restrict it?"

Because the restriction is a promise. If you hand someone a stack they cannot peek at the middle or reorder it, so the structure only has to maintain its top, and a smaller promise can be kept very cheaply.

§3Two ways to build one

In an array (code in array_stack.pyArrayStack.java): keep the items in an array data and a counter size; the top lives at index size − 1.

def push(self, e):    if self._size == len(self._data):        self._resize(2 * len(self._data))    self._data[self._size] = e    self._size += 1 def pop(self):    if self.is_empty():        raise IndexError("stack is empty")    self._size -= 1    e = self._data[self._size]    self._data[self._size] = None      # forget the item    return e
public void push(E e) {    if (size == data.length) {        resize(2 * data.length);    }    data[size] = e;    size++;} public E pop() {    if (isEmpty()) {        throw new NoSuchElementException("stack is empty");    }    size--;    E e = data[size];    data[size] = null;                 // forget the item    return e;}

When the array is full, push allocates an array of twice the length and copies the items over. Starting at capacity 2 and pushing 3, 7, 1, 9, 4, the capacity after each push is 2, 2, 4, 4, 8 (real output of stack_demo / StackDemo); the two resizes copy 2 and 4 items, 6 in all. Copying is expensive but rare: this is the dynamic array of Chapter 1, so push is amortized O(1).

PITFALL · Pop must forget the item.

After size--, the old slot still holds a reference to the popped object. Setting it to None / null lets the object be freed; without that line the stack silently keeps alive things it no longer contains.

PREDICT

A stack starts with capacity 2. After how many pushes does its capacity first become 8, and how many items have been copied by then?

Show the answer

After the 5th push (capacity 2 → 4 at the third push, 4 → 8 at the fifth), having copied 2 + 4 = 6 items.

In a chain of nodes (linked_stack.py, LinkedStack.java): each item lives in a small Node holding the item and a reference to the next node; the stack keeps a head and a size. push creates a node whose next is the old head and makes it the new head; pop reads the head's item and moves head to the next node. No copying, ever, and every call is O(1) in the worst case, not only on average. The price: one extra reference (and in Java one extra object) per item. Pushing a, b, c and popping returns c, b, a again: linked top: c size: 3 and linked pop order: c b a in the demo output.

§4In the standard library

In Python you rarely write your own stack: a plain list already is one. append pushes, pop() removes from the end, and lst[-1] is the top. collections.deque works the same way (append, pop) and is also what you want for queues, the next video.

Java has an old class java.util.Stack. Avoid it: it extends Vector, so every method is synchronized (time you do not need), and it exposes index-based methods that reach into the middle and break the stack promise. The documentation itself recommends the Deque interface; ArrayDeque has push, pop and peek and is the stack to use.

Queues: circular array and linked

A queue hands items back in the order they arrived: first in, first out. Storing it in an array with the front at index 0 forces a shift on every dequeue, so we move the front instead and bend the array into a circle; the remainder operator does the wrapping. The alternative is a chain with a head and a tail.

Queues: circular array and linkedVideo in preparation.
IN THIS CHAPTER§1 First in, first out§2 Why shifting is the wrong idea§3 Bend the array into a circle§4 The linked queue§5 In the standard library

§1First in, first out

A queue serves requests in the order they arrived: enqueue(e) adds at the rear, dequeue() removes and returns the item at the front, first() looks at the front, and size() / is_empty() count. All of them should be O(1).

§2Why shifting is the wrong idea

The obvious array layout keeps the front at index 0. Then every dequeue leaves a hole at the start and the other items shift one place left: n − 1 moves per dequeue, so almost all the time goes into shuffling items that did nothing. The fix is to move the front instead of the items: keep a front index, and let dequeue clear the cell and add one to it.

But then the occupied part creeps to the right and the rear runs off the end although there are free cells at the start.

§3Bend the array into a circle

When the rear reaches the last cell, the next position is cell 0: the array wraps around. With the capacity N, the next free cell is

(front + size) mod N,

and dequeue moves the front to (front + 1) mod N. No item is ever moved, so every operation is O(1) (code in array_queue.pyArrayQueue.java).

A queue in a circular array

The array drawn as a ring with cells 0–3, a front marker and a rear marker (the next free cell). Enqueue A B C D, dequeue twice, enqueue E F: they land in cells 0 and 1 and the formula (front + size) mod N is shown with its numbers. One more enqueue turns the ring into a bigger array: the items are copied in queue order and the front goes back to 0.

The real output of the demo (capacity 4; _ is an empty cell):

steparrayfrontsize
enqueue A, B, C, D[A, B, C, D]04
dequeue twice (A, B)[_, _, C, D]22
enqueue E, F[E, F, C, D]24
enqueue G (full: resize)[C, D, E, F, G, _, _, _]05
PREDICT

The state is [E, F, C, D] with front 2 and size 4, and G is enqueued. What does the array look like afterwards, and why is the front 0?

Show the answer

The queue is full, so enqueue allocates an array of capacity 8 and copies the items in queue order starting at the front: C, D, E, F go to cells 0–3, then G to cell 4: [C, D, E, F, G, _, _, _]. Copying in queue order straightens the circle out, so the front goes back to 0. Copying old[0..3] straight across would give E, F, C, D: the wrong order.

PITFALL · Copy in queue order.

A resize that ignores front breaks FIFO as soon as the queue has wrapped. Test with a queue that has wrapped before it grows.

§4The linked queue

The other way is a chain of nodes with a reference to both ends: head is the front and tail is the rear. enqueue adds a node after the tail and moves the tail; dequeue removes the head node and moves the head. Every operation touches one end only: O(1) (linked_queue.py, LinkedQueue.java). Why add at the tail and remove at the head, not the other way round? A chain can only step forward: removing at the tail would mean walking from the head to find the node before it.

NOTE · The tail must be cleared when the queue empties.

When dequeue removes the last node, set tail to None / null as well. Otherwise the tail still points at a node that is no longer in the queue, and the next enqueue hangs a node on it.

§5In the standard library

Use collections.deque as a queue: append enqueues at the right, popleft dequeues from the left, both O(1). Do not use list.pop(0): it is exactly the shifting we started with, moving every remaining item on every call, so it is O(n).

Java has a Queue interface and ArrayDeque is the implementation to reach for: it is a circular array like ours. Every operation comes in two versions: add / remove / element throw an exception when they cannot do their job, offer / poll / peek report failure (poll returns null on an empty queue). LinkedList also implements Queue, but ArrayDeque is usually faster because it keeps the items together in one array.

§1Both ends

A deque supports add_first, add_last, remove_first, remove_last, and first / last to look. Use only one end and you have a stack; add at one end and remove at the other and you have a queue. So the deque is the most general of the three structures in this chapter.

You might expect that being more flexible must cost more. It does not have to: a good deque does all four end operations in constant time. But that depends on how it is stored.

§2A circular array: the front can step backwards

add_last works exactly like enqueue (the item goes to (front + size) mod N), and remove_first is dequeue. The new move is add_first: step the front one cell backwards, modulo the capacity, and put the item there. From cell 0 one step back lands on the last cell: the front wraps below zero. remove_last clears the cell at (front + size − 1) mod N and reduces the size. Four operations, each a constant number of steps (circular_deque.py, CircularDeque.java).

A deque wraps at both ends

The ring of Video 2 with all four buttons. From the state B at cell 0 (front 0), add_first A moves the front to cell 3 (the arrow wraps below zero and the formula (front − 1) mod N is shown), then add_last C and D fill the ring. remove_first and remove_last take the two ends away.

The real output of the demo (capacity 4):

steparrayfrontsize
add_last B[B, _, _, _]01
add_first A[B, _, _, A]32
add_last C, D[B, C, D, A]34
remove_first (A), remove_last (D)[B, C, _, _]02
PREDICT

The deque is empty with capacity 4 and front 0. You call add_first(X). In which cell does X go, and what is the front afterwards?

Show the answer

Cell 3: the front steps back from 0 to (0 − 1) mod 4 = 3 and X is stored there, so the front is 3 and the size is 1. Items added with add_last afterwards go to cells 0, 1, 2, after X in the queue order.

PITFALL · The remainder of a negative number.

In Python (front − 1) % n is already in 0 … n − 1 (-1 % 4 == 3), so the one-liner works. In Java -1 % 4 == -1, and an index of −1 crashes. Write (front - 1 + n) % n (as CircularDeque.java does) or Math.floorMod(front - 1, n).

§3A chain: you need two links

With a chain of nodes, add_first and remove_first are easy at the head, and add_last is easy if you keep a tail reference. But remove_last is a problem in a singly linked chain: you need the node before the tail, and the only way to find it is to walk from the head: n − 1 steps. The fix is to give every node two links, next and prev: the tail knows its predecessor, and all four operations are O(1). That is a doubly linked list, built in Chapter 2.

§4An application: palindromes

Put every letter or digit of the text, in lower case, into a deque (skip spaces and punctuation). Then repeat: take the first item off the front and the last off the back; if they differ it is not a palindrome. If they agree until fewer than two items are left, it is. Each item is handled once with constant work: O(n). From the demo: racecar → True; A man, a plan, a canal: Panama → True; stack → False.

§5In the standard library

collections.deque is a deque: appendleft / append add at the two ends, popleft / pop remove from them, d[0] and d[-1] look. All four end operations are O(1). It also takes a maxlen: when it is full, adding at one end silently drops an item from the other end, which is handy for keeping only the most recent items.

The Deque interface describes exactly these operations (addFirst, addLast, removeFirst, removeLast, peekFirst, peekLast), and ArrayDeque is the implementation to use: a circular array like ours. Two things to know: ArrayDeque does not allow null (null is how poll and peek report an empty deque), and, as for queues, each operation has a version that throws and one that returns null.

§1Brackets: counting is not enough

Does every opening bracket have a closing bracket of its own kind? That test accepts a[b(c]d)e (one round pair, one square pair) but the brackets cross, which is not allowed: brackets must nest like boxes inside boxes. The rule is: the bracket you close must be the one you opened most recently. Most recent: that is a stack.

Read the text from left to right. At an opening bracket, push it. At a closing bracket, pop the stack and check that the two are a pair. Ignore other characters. At the end the stack must be empty (code in brackets.pyBracketMatcher.java).

Matching brackets with a stack

The string with a scan pointer above it and a vertical stack beside it. Step reads one character: openers are pushed, closers pop and flash green (match) or red (mismatch). The three failing cases ([)], ()) and ((()) stop with a labelled reason; a balanced string ends with an empty stack and a check mark.

There are three ways to fail, all caught by the same loop:

PREDICT

(() has one more opener than closers. Which of the three failures reports it?

Show the answer

The leftover opener: the ) is matched with the second (, the first ( is still on the stack when the text ends, and the final "stack is empty" check fails. A string with an extra closer fails with underflow instead.

§2Level order with a queue

A different problem: a small network. From A you can go directly to B and C; from B to D and E; from C to F; E also leads to F. We want to visit every node nearest first: A, then everything one step away, then everything two steps away. That is level order, or breadth-first search (BFS).

Put A in a queue. Repeat: take the front node out of the queue and visit it, and put each neighbour not seen before at the back. The seen set stops a node such as F, reachable from both C and E, from entering the queue twice.

Real output of the demo (level_order / LevelOrder), the queue after each visit:

visitqueue afterwards
AB, C
BC, D, E
CD, E, F
DE, F
EF
F(empty)

The visiting order is A, B, C, D, E, F: all the nodes one step away before any node two steps away. A queue gives the right order because it is first in, first out: nodes found earlier are explored earlier, and nodes found earlier are nearer.

PREDICT

What is the queue right after C has been visited, and why is F not added a second time when E is visited?

Show the answer

After visiting C the queue is D, E, F (F joined as C's neighbour). When E is visited, F is already in the seen set, so it is not enqueued again.

NOTE · Swap the queue for a stack and the same loop dives deep along one path before coming back.

That is depth-first search; we compare the two in Chapter 9.

§3How fast, and in the standard library

The bracket checker looks at each character once and does constant work for it: O(n) for a text of length n. Level order enqueues and dequeues each node once and looks at each neighbour list once: O(n + m) for n nodes and m edges, a count we use again in Chapter 9.

In real code the bracket checker's stack is a list (append, pop) and the search's queue is a collections.deque (append, popleft).

In real code use an ArrayDeque for both: as a stack with push and pop in the bracket checker, and as a queue with offer and poll in the search.

§2Check your understanding

1. You push 4, then 8, then 15 on an empty stack and pop twice. What does top() return now?

The pops return 15 and 8, so only 4 is left.

2. A circular-array queue has capacity 5, front 3 and size 4. In which cell does the next enqueue store its item?

(front + size) mod capacity = (3 + 4) mod 5 = 2; cell 7 does not exist.

3. A singly linked list keeps a head and a tail reference. Which operation is not O(1)?

You need the node before the tail and can only find it by walking from the head: n − 1 steps.

4. The bracket checker reads ((()). What does it report, and why?

Every closer finds a partner; the leftover opener is caught by the final "stack is empty" check.

5. An AI writes dequeue as items.pop(0) on a Python list and says it is O(1) because it is one operation. What is wrong?

A hidden loop inside the call; use collections.deque.popleft() (Python) or ArrayDeque (Java).

PROOFS

Exercise 1 · The invariant of a circular queue. A queue is stored in an array data of capacity N, with an index front (0 ≤ front < N) and a count size (0 ≤ size ≤ N). Write cell(k) = (front + k) mod N. The invariant is: for 0 ≤ k < size, data[cell(k)] holds the k-th item (k = 0 is the oldest), and every other cell holds None. (a) Prove that cell(0), cell(1), …, cell(N−1) are pairwise different. (b) Prove that the invariant holds for an empty queue and is kept by enqueue (when size < N the item goes to cell(size)) and by dequeue (which sets front to (front + 1) mod N). Say where (a) is used. (c) Prove that the invariant is also kept when a full queue is first copied into an array of twice the length in queue order starting at cell 0. (d) Why can the queue not do without size, keeping only front and rear = (front + size) mod N? Count the states.

Solution

Notation: cell(k) = (front + k) mod N. Invariant I: for 0 ≤ k < size, data[cell(k)] holds the k-th item (k = 0 the oldest), and every other cell holds None.

(a) Suppose 0 ≤ k < l ≤ N − 1 and cell(k) = cell(l). Then (front + k) ≡ (front + l) (mod N), so N divides l − k. But 0 < l − k < N, so this is impossible. Hence cell(0), …, cell(N−1) are pairwise different: the N cells are visited exactly once each as k runs from 0 to N − 1.

(b) Empty queue: size = 0, so I says that every cell holds None, which is how the array is created. ✓ enqueue with size < N: the item goes to r = (front + size) mod N = cell(size). By (a), cell(size) differs from cell(k) for every k < size, so by I the cell r holds None: nothing is overwritten. After the call the size is size + 1 and the item is at cell(size), the new last position; the other items are untouched, so I holds. dequeue with size > 0: the call returns data[front] = data[cell(0)], the oldest item, sets that cell to None, sets front′ = (front + 1) mod N and size′ = size − 1. Now cell′(k) = (front′ + k) mod N = cell(k + 1), so the items that were at positions 1 … size − 1 are at positions 0 … size′ − 1 under the new front. The vacated cell(0) is not among cell′(0..size′−1) = cell(1..size−1), by (a), and it holds None. So I holds. ∎

(c) Before the copy size = N. The copy walks the old array from front in queue order and stores item k in cell k of the new array of capacity 2N, then sets front = 0. Then cell′(k) = (0 + k) mod 2N = k for k < N = size, so item k is at cell′(k) and the cells N … 2N − 1 hold None: I holds for the new array. The enqueue then continues as in (b) with size = N < 2N.

(d) If only front and rear = (front + size) mod N are stored, the empty queue (size 0) and the full queue (size N) have the same rear: (front + 0) mod N = (front + N) mod N. So the pair (front, rear) cannot tell empty from full. Counting: the queue has N · (N + 1) states (N values of front, N + 1 values of size) but the pair (front, rear) takes only N · N values, so some states must share a pair. The fix is to store size (as the code does), or a boolean flag, or to leave one cell always unused (capacity N − 1 effectively).

Exercise 2 · Why the bracket checker is correct. Consider the three kinds of brackets ( ), [ ], { }; all other characters are ignored. A nesting of a string s is a set of pairs of positions (i, j) with i < j, where s[i] is an opener, s[j] is a closer of the same kind, every bracket of s is in exactly one pair, and no two pairs cross (there are no pairs (i, j) and (k, l) with i < k < j < l). Call s balanced if it has a nesting. The checker from video 4 pushes openers, and at a closer pops the top and compares kinds; it returns False on a mismatch or when the stack is empty at a closer, and at the end it returns whether the stack is empty. (a) Prove the stack invariant: after each character (if the checker has not returned False yet) the stack holds exactly the positions of the openers read so far that have not been popped, in increasing order from bottom to top. (b) Prove: if the checker returns True, then s is balanced (the pairs (popped opener, closer) form a nesting). (c) Prove: if s is balanced, the checker returns True. (d) Name, for each of ([)], ()) and ((()), the line of the checker that returns False and why.

Solution

(a) Stack invariant S(p): after the first p characters, if the checker has not returned False, the stack holds exactly the positions of the openers among them that have not been popped, in increasing order from bottom to top. Induction on p. p = 0: both are empty. Step p → p + 1 with character c:

  • c is an opener: it is pushed, and its position is larger than every position already on the stack, so the order is kept and the stack is the old set plus this opener. ✓
  • c is a closer: if the stack is empty the checker returns False, which the statement excludes. Otherwise it pops the top, the largest position on the stack; if the kinds differ it returns False (excluded); else the stack is the old stack without its top, still in increasing order, and the popped opener is no longer unpopped. ✓
  • c is another character: nothing changes. ✓

(b) True ⇒ balanced. Let P be the set of pairs (position of the popped opener, position of the closer), one per closer. Each pair has i < j (the opener was read before), the kinds match (otherwise False), every closer is in exactly one pair (it pops exactly one opener, otherwise False at an empty stack), and every opener is in exactly one pair: an opener that was pushed is either popped once, or is still on the stack at the end, but the checker returned True only because the stack is empty at the end. No crossing: suppose (i, j) and (k, l) in P with i < k < j < l. When the closer at j is read, S says that the stack is in increasing position order and that j pops i. The opener at k satisfies i < k < j, so k was pushed after i and before j; it is not popped before j (its pop happens at l > j), so it is on the stack at that moment and above i (larger position). But j pops the top of the stack, which is above i: it would pop k or something above k, not i. Contradiction. So P is a nesting. ∎

(c) Balanced ⇒ True. Let P be a nesting. Claim: the brackets strictly between a pair (i, j) are paired among themselves. Take a bracket at k with i < k < j and its partner m. If k is an opener then m > k; m > j would give i < k < j < m, a crossing, so m < j. If k is a closer then m < k; m < i would give m < i < k < j, a crossing, so m > i. Either way m is also strictly between i and j. Now run the checker. Claim: at every closer at position j with partner i in P, the checker finds i on top of the stack, so the pop succeeds and the kinds match (P pairs equal kinds). Proof by induction on the closers in left-to-right order. At the time j is read, i has been pushed and not popped: the only closer that can pop it is j, because by the induction hypothesis every earlier closer popped its own partner (which is not i). Every opener at k with i < k < j has been popped already, because its partner is a closer before j (by the first claim), which popped it by the induction hypothesis. So the top of the stack is i. At the end every opener has been popped by its own partner, so the stack is empty and the checker returns True. ∎

(d) ([)]: at ) the top of the stack is [; the line that compares the kinds of opener and closer returns False (mismatch). ()): at the second ) the stack is empty; the check "stack empty at a closer" returns False (underflow: nothing to match). ((()): all three closers match, but at the end one ( is still on the stack; the final return stack is empty is False (leftover opener). The same loop catches all three; counting openers and closers cannot: ([)] has one of each kind.

Exercise 3 · A queue from two stacks. Build a queue from two stacks inbox and outbox: enqueue(x) pushes x on inbox; dequeue() first, if outbox is empty, pops every item from inbox and pushes it on outbox, and then pops outbox. (a) Show that this is a correct queue: state an invariant relating the two stacks to the queue order, and prove it. (b) Cost model: every push and every pop on a stack costs 1. Show that one dequeue can cost Θ(n). (c) Use the accounting method from chapter 1 to prove that any sequence of operations with e enqueues costs at most 4e, so the amortized cost per operation is O(1). (d) A variant moves everything back to inbox after every dequeue so that inbox always holds the whole queue. Show a sequence of 2n operations that costs Θ(n²) with it.

Solution

(a) Invariant: reading outbox from top to bottom, followed by inbox from bottom to top, lists the queue from front to rear. Empty: both empty. enqueue(x) pushes x on top of inbox, which is its last position in "bottom to top" reading: x is appended at the rear. ✓ dequeue with outbox non-empty: pops the top of outbox, which is the first item in the reading, i.e. the front. ✓ dequeue with outbox empty: the queue is inbox bottom to top, say x₁ … xₘ. Popping inbox yields xₘ, …, x₁ and pushing them on outbox leaves x₁ on top: reading outbox top to bottom gives x₁ … xₘ and inbox is empty, so the reading is unchanged. ✓ Then the pop takes x₁, the front. ∎

(b) Put n items in with enqueue (cost n), then dequeue: it pops n items from inbox (n), pushes n on outbox (n) and pops one (1): 2n + 1 = Θ(n) for this one call.

(c) Charge 4 coins per enqueue and 0 per dequeue. An enqueue spends 1 coin on its own push and stores 3 coins on the new item. Over its life an item can cause only these operations: its push on inbox (paid by the enqueue), its pop from inbox and its push on outbox during a transfer, and its pop from outbox by a dequeue. An item moves from inbox to outbox at most once, because items leave outbox only by being dequeued and nothing ever goes back. So the three remaining operations cost at most 3 coins per item, exactly what it stores. Every dequeue's work is the sum of those operations, so the stored coins pay for all of it and the account never goes negative. A sequence with e enqueues therefore costs at most 4e in total (dequeues that find an empty queue are errors and are not counted). Since the number of dequeues is at most e, the total over all operations is at most 4e ≤ 4 · (number of operations), so the amortized cost per operation is O(1). (Run it: test_ex3_claims.py counts the unit operations on random sequences and checks cost ≤ 4e.)

(d) In the variant, each enqueue first moves everything from outbox back to inbox, and each dequeue moves everything from inbox to outbox. Start with n items in the queue and alternate dequeue, enqueue n times: every dequeue transfers the whole queue (about n − 1 or n items, each costing 2) and every enqueue moves it back (again about 2n), so each pair costs about 4n and the 2n operations cost about 4n² = Θ(n²), against at most 4n for the real design. The argument of (c) breaks because an item can now move many times.

Exercise 4 · Choose the structure. For each situation choose a stack, a queue or a deque, array-based or linked, say which operations you use and what each costs, and say what would go wrong with a plain stack or a plain queue. (a) An editor keeps the last 100 edits for Undo; edit 101 makes it forget the oldest. (b) A printer serves jobs in the order they were submitted, and the number of jobs is not known in advance. (c) A browser's Back and Forward buttons. (Visiting a new page empties Forward.) (d) A server keeps its last 5 log lines for a status page. (e) Given n readings and a window size k, report the maximum of every window of k consecutive readings in O(n) total time. Describe what your structure holds at each step and argue the total cost.

Solution
StructureOperations (cost)Why not a plain stack / queue
(a)Deque, a circular array of capacity 100add newest at the rear (O(1)); Undo = remove the newest from the rear (O(1)); when it holds 100 edits, remove the oldest from the front first (O(1))A stack cannot drop its bottom item; a queue cannot remove the newest
(b)Queue, linked chain with head and tail (or a circular array that doubles)enqueue at the tail, dequeue at the head, O(1) each; no capacity to chooseA stack would serve the newest job first
(c)Two stacks, back and forwardvisit: push the current page on back, discard forward (O(1) if you just drop the stack); Back: push the current page on forward, pop back; Forward: the symmetric move; all O(1)One stack cannot go both ways; each button is "give me the most recent": a stack
(d)Circular buffer of capacity 5 (a deque with a maximum length)append at the rear; when full, the oldest line is overwritten, O(1); reading the 5 lines is O(5)An unbounded queue would grow forever; a stack gives the wrong order
(e)Deque of indicessee below, O(1) per step, O(n) in allNeither: items leave from both ends

For (e) keep in the deque the indices of the readings that can still become the maximum of a future window, so that their values decrease from front to rear. For each new reading a[i]: remove from the rear every index whose value is ≤ a[i] (it can never be the maximum while a[i] is in the window, because a[i] is newer and at least as large); append i; if the front index is i − k (it fell out of the window), remove it from the front; once i ≥ k − 1 the maximum of the current window is a[front]. Example a = 1, 3, −1, −3, 5, 3, 6, 7 with k = 3 gives 3, 3, 5, 5, 6, 7. Each index is appended once and removed at most once, so there are at most 2n deque operations, each O(1): O(n) in total, against O(nk) for rescanning every window. (test_ex3_claims.py checks the example, compares with brute force and counts the operations.)

Exercise 5 · A stack that knows its minimum. Design a stack of numbers with push, pop, top and min_value (the smallest number currently in the stack), each in O(1) worst-case time. (a) Describe the design (a second stack is enough) and give the code for push and pop. (b) State and prove the invariant that makes min_value correct. (c) Your push compares with ≤ or <. Find a sequence of operations that breaks the other choice. (d) How much extra space does the design use in the worst case and in the best case? Give a one-stack alternative.

Solution

(a) Keep the items on main and, on mins, those items that are at most every item below them.

push(x):  main.push(x);  if mins is empty or x <= mins.top():  mins.push(x)pop():    x = main.pop();  if x == mins.top():  mins.pop();  return xmin_value():  return mins.top()

(b) Invariant: mins contains exactly the items of main that are ≤ every item below them in main, in the same order; in particular mins.top() = the minimum of main (and mins is empty iff main is). Push of x: if x ≤ the current minimum (mins.top()), x is ≤ everything below it, so it belongs to mins and is pushed there, and it is the new minimum; otherwise x has a smaller item below it, so it does not belong, mins is unchanged and the minimum is unchanged. Pop of x: the top item x of main has the property "≤ everything below" exactly when x equals mins.top() (if it has the property it is the last such item in order, so it is mins.top(); if it does not, some item below is strictly smaller, so the minimum of main, which is mins.top(), is smaller than x and differs from it). So testing x == mins.top() decides correctly whether x must leave mins, and after the pop the invariant holds again. Every operation does at most one push or pop on each stack: O(1) worst-case. ∎

(c) With < instead of ≤: push 2, push 2, pop. After the pushes mins holds only the first 2 (the second was not smaller). The pop removes a 2 from main, sees that it equals mins.top() and pops mins, which is now empty, although main still holds a 2: min_value() fails (or returns garbage). With ≤ both 2s are on mins, and one stays after the pop. (Checked in test_ex3_claims.py.)

(d) Worst case: pushing a strictly decreasing sequence makes every item a new minimum, so mins has n entries and the total is 2n items; best case: an increasing sequence leaves mins with 1 entry. Alternative: store pairs (x, minimum of everything at or below x) on one stack: always exactly 2n numbers, with simpler code (min_value is the second part of the top pair).

Solution

Reference: solutions/py/ex3_stack.py, solutions/java/Ex3Stack.java. push checks size == capacity first, copies item by item into an array of twice the length (adding 1 to copies per item), then stores the item at index size; pop decrements size, reads the item and writes None / null into the freed slot (otherwise the array keeps the object alive); top and pop throw on an empty stack. Copies: the resizes happen at capacities 2, 4, 8, …, C/2 and copy that many items, so the total is 2 + 4 + … + C/2 = C − 2 when the final capacity is C (for C = 2 there is no resize and C − 2 = 0). After n pushes C is the smallest power of two that is ≥ n (and ≥ 2), so C < 2n for n ≥ 2 and the total C − 2 < 2n; for n = 1 the total is 0 < 2. As in chapter 1: fewer than 2n copies in total, so fewer than 3n steps counting the writes, amortized O(1) per push. The capacity sequence for 9 pushes is 2, 2, 4, 4, 8, 8, 8, 8, 16.

Exercise 9 — RingQueue in read/py/ex3_read.py / Ex3Read.RingQueue in read/java/Ex3Read.java.

Solution

The bug: dequeue does self._front += 1 (Java: front++) and never takes the remainder, while enqueue computes (front + size) % capacity and does wrap. For RingQueue(3): enqueue 1, 2, 3, dequeue three times (front is now 3 = capacity), enqueue 4 (it lands in cell (3 + 0) % 3 = 0, correctly), and now dequeue: it reads data[3] from an array of length 3 and fails with an IndexError (Java: ArrayIndexOutOfBoundsException). The AI's test enqueued three, dequeued three and enqueued once more but never dequeued after the front had reached the capacity, so the line that fails never ran. In general the queue works for exactly capacity dequeues and then breaks. Fix: self._front = (self._front + 1) % len(self._data). The test that catches it: do more than a full lap of operations (more than capacity dequeues in total, with the queue never empty for long) and compare with a trusted reference, such as collections.deque / ArrayDeque, on a long random sequence: the same test as in Exercise 7. The "O(1)" claim is true; the bug is in the claim of testing, not in the complexity. (The test test_buggy_ring_queue_fails_on_the_fourth_dequeue and test_buggy_ring_queue_needs_exactly_capacity_dequeues in solutions/py/test_ex3_read.py show the failure for capacities 1, 2, 3 and 5.)

Exercise 10 — is_matched in read/py/ex3_read.py / isMatched in read/java/Ex3Read.java.

Solution

Two bugs. (1) stack.pop() on an empty stack: for ")", "())" or "a]", a closer arrives with nothing to match and Python raises an IndexError (Java: NoSuchElementException from ArrayDeque.pop) instead of returning False. (2) The loop ends with return True (Java return true): leftover openers are never noticed, so "((", "([" and "((())" are reported as balanced. Why the three tests passed: ([]{}) and (a[b]c) are balanced, and [(]) fails on a mismatch inside the loop, the only failure kind the code handles; none of the tests exercised underflow or a leftover opener. if not stack: return False        # before popping at a closer...return not stack                  # at the end

The test that catches it: one test per way to fail (mismatch, underflow, leftover), the empty string, and, best, all strings up to length 8 over a small alphabet compared with an independent definition (balanced_by_grammar in solutions/py/ex3_claims.py does that for Exercise 2).

§4Working with AI

AI assistants write stacks and queues all the time, and the mistakes are predictable. Treat the code as a hypothesis and test it:

  1. Hunt for hidden O(n). Python: list.pop(0), list.insert(0, x), x in some_list. Java: ArrayList.remove(0) and add(0, x), LinkedList.get(i), Stack.search. A queue built on pop(0) is quadratic overall.
  2. Reject the legacy class. If the answer uses java.util.Stack or Vector, ask for ArrayDeque. If a deque rejects null (Java), check that the code never stores one.
  3. Test more than one lap. For a circular array, run more operations than the capacity, with the queue wrapping several times, and compare with a trusted reference (collections.deque, ArrayDeque) on a long random sequence. The bug in Exercise 9 survives every test that stays inside the first lap.
  4. Test the three ways to fail. For anything with a stack (brackets, postfix, undo): a mismatch, an empty stack where an item is needed, and something left over at the end (Exercise 10).
  5. Ask for the invariant. "State the invariant of your circular queue" should produce (front + k) mod N for the k-th item; if it cannot, the indices are probably wrong. Then put it in as an assert that runs after every operation.
PITFALL · Both languages hide the same trap in different places.

Python's % is non-negative for a positive modulus; Java's is not. A circular deque that works in a Python translation of the code can crash in Java on the first add_first.
