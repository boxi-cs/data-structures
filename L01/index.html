Complexity and Proof MethodsData Structures · Chapter 1

Two programs can give the same correct answer and still differ by a factor of a million in how long they take. This chapter gives you the tools to tell which is which before you run anything: count steps, describe their growth with Big-O, prove bounds with witnesses, average a rare expensive step over many cheap ones, and prove that a loop does what you claim with induction and invariants.

Why this matters

about 90–120 minutes (4 videos of 8–12 minutes plus the exercises).

Choose by growth, not by stopwatch

Seconds depend on the machine, the language and what else is running; the number of steps as a function of n does not.

Every structure in this course is a trade

Arrays, linked lists, trees, hash tables and heaps are fast at some operations and slow at others; Big-O is the language in which we state the trade.

Claims need proofs, including the ones an AI makes

Witnesses, induction and loop invariants are how you check that "this is O(n)" is true.

§1Same answer, very different cost

Program A compares every pair of items; Program B walks the list once and remembers what it has seen (code in code/py/duplicates.pycode/java/Duplicates.java). Both are correct. On a thousand items you cannot tell them apart.

The machine, the language and the other programs running all change the number. The step count does not.

§3The doubling test

Double n and watch the count: ×2 means linear, ×4 means quadratic. It is the quickest test you have, and it works on measurements and on counts.

Double n, watch the count

Table of n, T(n), T(2n)/T(n) for Program A and Program B; the ratio column settles at 4 and 2.

PITFALL · One measurement is not a comparison.

Time both programs on lists with no duplicate (the worst case: they must look at everything), at several sizes. In Java also warm up the JIT first and take the best of several runs, otherwise the first sizes are measured while the code is still being compiled (our first Java run did not even quadruple).

§4Big-O keeps the dominant term

n(n−1)/2 = ½n² − ½n. For large n the n² term dominates; drop the smaller term and the constant factor ½ (the constant depends on the machine anyway). What is left is the shape: T(n) = O(n²) for Program A and T(n) = O(n) for Program B. The names to know: O(1) constant, O(log n) logarithmic, O(n) linear, O(n²) quadratic.

NOTE · We count a set lookup as one step.

That is fair for the right kind of set; chapter 7 explains why and when it is not.

In Python, x in seen is one step when seen is a set and up to n steps when it is a list (see Exercise 9).

In Java, seen.add(x) is one step on a HashSet and seen.contains(x) up to n steps on an ArrayList (see Exercise 9).

Proving asymptotic bounds

"Drop constants and smaller terms" is a rule of thumb; this video turns it into a definition you can prove. f(n) = O(g(n)) means there are constants c and n₀ with f(n) ≤ c·g(n) for every n ≥ n₀. We find such witnesses, meet Ω and Θ, and learn how to show that a bound does not hold.

O, Ω, Θwitnesses c and n₀upper, lower, tightnon-examples
Proving asymptotic boundsVideo in preparation.
IN THIS CHAPTER§1 The definitions§2 A worked example§3 Showing a bound is false§4 The growth ladder

§1The definitions

  • f(n) = O(g(n)) (upper bound): there exist c > 0 and n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀.
  • f(n) = Ω(g(n)) (lower bound): there exist c > 0 and n₀ such that f(n) ≥ c·g(n) for all n ≥ n₀.
  • f(n) = Θ(g(n)) (tight bound): both.

The pair (c, n₀) is a witness. To prove a Big-O claim, produce a witness and check the inequality for every n ≥ n₀.

Witnesses for f(n) = 3n² + 10n + 5 = O(n²)

Plots f(n) = 3n² + 10n + 5 and c·n² on the same axes. The region n ≥ n₀ is shaded; the badge turns green only when c·n² stays above f over the whole shaded region. Presets: (c, n₀) = (5, 10) works, (4, 1) fails at n = 1.

§2A worked example

3n² + 10n + 5 = O(n²). Take n₀ = 10. For n ≥ 10: 10n ≤ n² and 5 ≤ n², so 3n² + 10n + 5 ≤ 5n²: c = 5 works. (Other witnesses work too, for example c = 18 with n₀ = 1; Exercise 1 asks you to do this yourself.)

PREDICT

Is n log n = O(n²)? Is n² = O(n log n)?

Show the answer

Yes to the first: log₂ n ≤ n for n ≥ 1 (Exercise 2(c) shows 2ⁿ ≥ n + 1), so n log₂ n ≤ n² with c = 1. No to the second: n² ≤ c·n log₂ n would mean n ≤ c·log₂ n for all large n, and n eventually beats any constant multiple of log₂ n.

§3Showing a bound is false

To show n² ≠ O(n), assume witnesses c and n₀ exist: n² ≤ c·n for all n ≥ n₀, so n ≤ c for all n ≥ n₀. Choose n larger than both n₀ and c: contradiction.

PITFALL · "=" is not equality.

"f(n) = O(g(n))" says f is at most of the order of g. n = O(n²) is true and almost useless; say Θ when you mean "exactly this order".

PITFALL · A constant in the exponent is not a constant factor.

2^(n+1) = O(2ⁿ) (factor 2) but 2^(2n) is not O(2ⁿ).

§4The growth ladder

1 ≺ log n ≺ n ≺ n log n ≺ n² ≺ n³ ≺ 2ⁿ ≺ n! (each is O of the next and not Ω of it). A sum you will use constantly: 1 + 2 + … + n = n(n+1)/2 = Θ(n²).

The ladder of growth rates

Amortized analysis

Some operations are usually cheap and occasionally expensive. A dynamic array's append copies the whole array when it is full, yet n appends cost fewer than 3n steps. We prove that two ways: the aggregate method (add it all up) and the accounting method (charge every append a little extra and save it for the rare expensive step).

IN THIS CHAPTER§1 The dynamic array§2 Aggregate method§3 Accounting method§4 In the standard library

§1The dynamic array

An array has a fixed capacity. When append finds it full it allocates a bigger one, copies every element, and then stores the new element. We start at capacity 1 and double. Cost model: 1 per element written, 1 per element copied.

Doubling or growing by one?

Boxes fill; when full, they copy into a doubled array (one copy per element, a running tally) . A second row does the same with "grow by 1", a third with "grow by 1000". A cost-per-append meter at the bottom.

PREDICT

Starting from capacity 1, which appends trigger a resize among the first 9, and how many copies in total?

Show the answer

Appends 2, 3, 5 and 9 (append i resizes when i − 1 is a power of two), copying 1, 2, 4 and 8 elements: 15 copies, and the capacity is 16 afterwards. The pattern: resizes at 2ʲ + 1 copying 2ʲ.

§2Aggregate method

The copies for n appends are 1 + 2 + 4 + … + 2ᴶ = 2^(J+1) − 1, where 2ᴶ ≤ n − 1, so fewer than 2n. Add the n writes: fewer than 3n in total, so at most 3 per append on average over the sequence.

§3Accounting method

Charge 3 coins per append: 1 pays for the write, 2 are saved on the new element. When the array of size m fills up, the m/2 elements added since the last resize hold m coins, which pay for copying all m. The account never goes negative.

NOTE · The proof shows the sum, not a probability.

Amortized O(1) is a worst-case guarantee about any sequence of operations, not about random inputs.

PITFALL · The growth rule matters.

Growing by 1 makes every append from the second on copy the whole array: n(n−1)/2 copies in all, Θ(n) per append. Growing by any constant amount has the same problem; multiply by a constant factor.

§4In the standard library

A Python list is a dynamic array. CPython over-allocates by roughly an eighth rather than doubling; any constant factor greater than 1 gives amortized O(1). insert(0, x) is the slow operation (Exercise 10).

ArrayList is a dynamic array that grows by about half (×1.5) when full. Any constant factor greater than 1 gives amortized O(1); add(0, x) is the slow operation (Exercise 10).

Induction and loop invariants

How do you know a loop or a formula is right for every n? Induction proves a statement for all n from a base case and a step. A loop invariant is induction applied to a loop: a fact true before the loop, kept true by every iteration, which gives the answer when the loop stops.

inductionbase caseinductive steploop invariantinitializationmaintenancetermination
Induction and loop invariantsVideo in preparation.
IN THIS CHAPTER§1 Induction§2 Loop invariants

§1Induction

To prove P(n) for all n ≥ n₀: (1) base case: prove P(n₀); (2) step: assume P(k) and prove P(k+1); (3) conclude P(n) for all n ≥ n₀. A worked proof: 1 + 2 + 4 + … + 2ᵏ = 2^(k+1) − 1 (Exercise 2(a)); it is exactly the sum that gave us the copy count in video 3.

Induction as dominoes

A row of dominoes labelled P(0), P(1), …; the base case tips the first, the inductive step is drawn as "if P(k) falls it knocks P(k+1)".

PREDICT

What goes wrong if you prove the step but skip the base case?

Show the answer

Nothing starts the chain. "n = n + 1" has a perfectly valid inductive step (add 1 to both sides) and is false for every n: no base case.

§2Loop invariants

A loop invariant is a statement about the variables that is true every time the loop condition is evaluated. To use it prove three things:

  1. Initialization: it is true before the first iteration.
  2. Maintenance: if it is true at the top of an iteration, it is true at the top of the next one.
  3. Termination: when the loop stops, the invariant plus the stopping condition give the result you want (and the loop does stop: something decreases).

Example: fast exponentiation (Exercise 5) with invariant result · baseᵉ = xⁿ. Before the loop it says 1 · xⁿ = xⁿ; each iteration squares the base and halves e (taking a factor out into result when e is odd); at e = 0 it says result = xⁿ.

A loop invariant in action

The code (the real fast_power file) with a pointer, the variables result, base, e in boxes, and a live line "result · base^e = x^n ✓" recomputed after every step. Choose x, n.

PREDICT

How many iterations does fast exponentiation run for n = 1000?

Show the answer

10: 1000 in binary has 10 bits (512 ≤ 1000 < 1024), and e loses one bit per iteration. Naively multiplying would take 999 multiplications.

PITFALL · Testing is not proving.

A test checks the cases you tried. An invariant is a claim about every iteration. Exercise 8 puts both side by side: the tests call a hook that checks the invariant at every iteration.

PROOFS

Exercise 1 · Big-O witnesses. Let f(n) = 3n² + 10n + 5. (a) Prove f(n) = O(n²) by giving explicit constants c and n₀ and checking the inequality for every n ≥ n₀. (b) Prove f(n) = Ω(n²). What do (a) and (b) together say about f? (c) Prove that n² is not O(n). (Suppose it is, and derive a contradiction.) (d) Is 2^(n+1) = O(2ⁿ)? Is 2^(2n) = O(2ⁿ)? Prove both answers.

Solution

Definitions (video 2): f(n) = O(g(n)) means there are constants c > 0 and n₀ such that f(n) ≤ c·g(n) for every n ≥ n₀; f(n) = Ω(g(n)) means f(n) ≥ c·g(n) for every n ≥ n₀; Θ means both.

(a) Take c = 5 and n₀ = 10. For every n ≥ 10 we have 10n ≤ n² (divide by n > 0: 10 ≤ n) and 5 ≤ n², so f(n) = 3n² + 10n + 5 ≤ 3n² + n² + n² = 5n². (Other witnesses work too, for example c = 18 and n₀ = 1: for n ≥ 1, 10n ≤ 10n² and 5 ≤ 5n², so f(n) ≤ 18n². Any valid pair is a correct answer; a pair is only "wrong" if the inequality fails for some n ≥ n₀. For instance c = 4 fails at n = 1 because f(1) = 18 > 4.)

(b) Take c = 3 and n₀ = 1. All three terms are non-negative, so f(n) ≥ 3n² for every n ≥ 1. Hence f(n) = Ω(n²). With (a), f(n) = Θ(n²): f grows exactly as fast as n², up to constant factors.

(c) Suppose n² = O(n): there are c > 0 and n₀ with n² ≤ c·n for all n ≥ n₀. Dividing by n > 0 gives n ≤ c for all n ≥ n₀. But n = max(n₀, ⌈c⌉ + 1) is at least n₀ and larger than c, a contradiction.

(d) 2^(n+1) = 2·2ⁿ, so c = 2 and n₀ = 0 give 2^(n+1) = O(2ⁿ): yes. 2^(2n) = (2ⁿ)². Suppose (2ⁿ)² ≤ c·2ⁿ for all n ≥ n₀. Dividing by 2ⁿ gives 2ⁿ ≤ c. By Exercise 2(c), 2ⁿ ≥ n + 1, so for n = max(n₀, ⌈c⌉) we get 2ⁿ ≥ n + 1 > c, a contradiction. So 2^(2n) is not O(2ⁿ): a constant in the exponent is not a constant factor.

Exercise 2 · Induction. (a) Prove by induction that for every k ≥ 0: 1 + 2 + 4 + … + 2ᵏ = 2^(k+1) − 1. (b) A dynamic array doubles its capacity from 1 to 2, 4, …, 2ᵏ, copying every stored element at each resize. Use (a) to compute the total number of elements copied. (c) Prove by induction that 2ⁿ ≥ n + 1 for every n ≥ 0. What does this say about log₂(n + 1)?

Solution

(a) Claim P(k): Σᵢ₌₀ᵏ 2ⁱ = 2^(k+1) − 1. Base k = 0: the sum is 2⁰ = 1 and 2¹ − 1 = 1. ✓ Step: assume P(k). Then Σᵢ₌₀^(k+1) 2ⁱ = (Σᵢ₌₀ᵏ 2ⁱ) + 2^(k+1) = (2^(k+1) − 1) + 2^(k+1) = 2·2^(k+1) − 1 = 2^(k+2) − 1, which is P(k+1). By induction P(k) holds for all k ≥ 0. ∎

(b) Going from capacity 2ʲ to 2^(j+1) copies 2ʲ elements (the array is full). Starting at capacity 1 = 2⁰ and ending at 2ᵏ, the resizes are j = 0, …, k − 1, so the total is Σⱼ₌₀^(k−1) 2ʲ = 2ᵏ − 1 by (a) with k − 1 (for k = 0 there is no resize and 2⁰ − 1 = 0 ✓). So the total copying is one less than the final capacity: if the final capacity is n = 2ᵏ, fewer than n copies in total.

(c) Claim: 2ⁿ ≥ n + 1. Base n = 0: 1 ≥ 1. ✓ Step: assume 2ⁿ ≥ n + 1. Then 2^(n+1) = 2·2ⁿ ≥ 2(n + 1) = 2n + 2 ≥ n + 2, because n ≥ 0. ∎ Taking log₂ of both sides: n ≥ log₂(n + 1), i.e. the logarithm grows more slowly than n (it is what lets us say log n = O(n)).

Exercise 3 · Amortized cost. A dynamic array starts with capacity 1 and size 0. An append into a full array (size = capacity) first doubles the capacity and copies every element; then it writes the new element. Cost model: 1 per element written by an append, 1 per element copied. (a) Aggregate: prove that n appends cost less than 3n in total. (b) Accounting: charge 3 coins per append. Explain what each coin pays for and prove the account never goes negative. (c) Now grow by 1 instead of doubling (capacity → capacity + 1 when full). Compute the total cost of n appends exactly, and the amortized cost per append in Θ-notation.

Solution

Set-up: appends are numbered 1, 2, …, n. Append i happens when the size is i − 1.

(a) The array is full exactly when the size equals the capacity. Capacity starts at 1 and doubles at each resize, so the capacity is always the smallest power of two that is at least the size (1 for sizes 0 and 1), and append i finds the array full exactly when i − 1 is a power of two, i − 1 = 2ʲ (append 2 with j = 0, append 3 with j = 1, append 5 with j = 2, …). That resize copies 2ʲ elements. For n ≥ 2 let J = ⌊log₂(n − 1)⌋, so 2ᴶ ≤ n − 1. The resizes among the first n appends are j = 0, …, J, and total copies = Σⱼ₌₀ᴶ 2ʲ = 2^(J+1) − 1 ≤ 2(n − 1) − 1 < 2n (by Exercise 2(a)). For n = 1 there are 0 copies. Writes cost n. Total cost = n + copies < n + 2n = 3n, so each append costs less than 3 on average over the sequence. ∎

(b) Charge 3 coins per append. One coin pays for writing the new element; the other two are stored on the new element. A resize at size m copies m elements and costs m. Claim: just before a resize at size m, the elements appended since the previous resize hold at least m unspent coins, enough to pay for it. For m = 1 (the first resize) the single element holds 2 ≥ 1 coins. For m ≥ 2 the previous resize happened at size m/2, so exactly m/2 elements have been appended since then, holding 2·(m/2) = m coins. Spending them leaves no coins on older elements (or only leftovers, which can only help). So the balance never goes negative, the real cost is at most the total charge 3n, and the amortized cost per append is O(1) (at most 3). ∎

(c) With growth by 1 the capacity always equals the size right after a resize, so every append i ≥ 2 finds the array full and copies i − 1 elements. Total copies = Σᵢ₌₂ⁿ (i − 1) = n(n − 1)/2. Total cost = n + n(n − 1)/2 = n(n + 1)/2, so the amortized cost per append is (n + 1)/2 = Θ(n), against O(1) for doubling. Growing by any constant amount k has the same problem (a resize every k appends, each copying a number of elements proportional to n); only multiplying the capacity by a constant factor greater than 1 gives O(1) amortized.

Exercise 4 · Pair sum. Given n integers and a target T, decide whether two different positions hold values that add up to T. Design three solutions: (A) check all pairs; (B) sort, then walk two pointers inward from both ends; (C) one pass with a hash set. For each give the running time as a function of n (state what you assume about sorting and hashing), the extra space, and one situation in which you would pick it. What does each cost for n = 1,000,000 (count steps, as in video 1)?

Solution

Assume a comparison sort in O(n log n) and a hash set with O(1) expected time per lookup and insert (chapter 7).

TimeExtra spacePick it when
A all pairsn(n−1)/2 = O(n²)O(1)n is tiny, or memory is very tight and the input must not be reordered
B sort + two pointersO(n log n) sort + ≤ n−1 pointer steps = O(n log n)O(1) if sorted in place (reorders the input), O(n) for a copythe data is already sorted (then O(n)), or hashing is not available / not trustworthy

Two pointers: i = 0, j = n − 1; while i < j: s = a[i] + a[j]; if s = T return found; if s < T then i++ else j−−. It is correct because if s < T then a[i] + a[k] ≤ s < T for every k ≤ j, so a[i] cannot be part of any answer among the remaining items and can be dropped; the case s > T is symmetric. Hash set: for each x in order, if T − x is already in the set return found, then add x. Checking before adding makes the two positions different (a value pairs with itself only if it occurs twice). Counts for n = 1,000,000: A ≈ 5·10¹¹ comparisons (the number from video 1); B ≈ n·log₂ n ≈ 2·10⁷ comparisons to sort plus at most 10⁶ pointer steps; C ≈ 10⁶ lookups and 10⁶ inserts. The caveat for C is that "expected O(1)" depends on the hash function; a bad one degrades toward O(n²).

Solution

Invariant: at the top of every iteration (every time the loop condition is evaluated), result · baseᵉ = xⁿ (with the convention b⁰ = 1, also for b = 0).

Initialization. Before the first iteration result = 1, base = x, e = n, so result · baseᵉ = 1 · xⁿ = xⁿ. ✓ Maintenance. Assume the invariant and e > 0 at the top of an iteration. Let result′, base′, e′ be the values at the top of the next one. If e is even: result′ = result, base′ = base², e′ = e/2, so result′ · base′^(e′) = result · (base²)^(e/2) = result · baseᵉ = xⁿ. ✓ If e is odd: result′ = result · base, base′ = base², e′ = (e − 1)/2, so result′ · base′^(e′) = result · base · base^(e−1) = result · baseᵉ = xⁿ. ✓ Termination. While e > 0, e′ = ⌊e/2⌋ < e and e′ ≥ 0 is an integer, so e strictly decreases and reaches 0 after finitely many iterations. When the loop exits, e = 0, so the invariant says result · base⁰ = result = xⁿ. The returned value is xⁿ. ∎ Cost. e is halved (rounded down) each time, so the loop runs ⌊log₂ n⌋ + 1 times for n ≥ 1 (the bit length of n) and 0 times for n = 0. Each iteration does one squaring and at most one more multiplication, so there are at most 2(⌊log₂ n⌋ + 1) = O(log n) multiplications, against n − 1 for the naive loop.

result = 1; base = x; e = nwhile e > 0:    if e is odd: result = result * base    base = base * base    e = e // 2return result

Design the loop invariant (one equation relating result, base, e, x and n). Prove initialization, maintenance (treat e even and e odd separately) and termination, and conclude that the returned value is xⁿ. Then count the iterations and the multiplications as a function of n.

Exercise 6 · Count the steps — ex_steps.pyExSteps.java. Write the loops and count their iterations, then write the closed form your analysis predicts and let the tests check that they agree. Includes a loop whose variable halves (count = ⌊log₂ n⌋) and a triple loop with i ≤ j ≤ k.

Solution

Closed forms (the tests check them against the loops):

  • count_pairs(n) = n(n−1)/2. Row i of the double loop has n − 1 − i iterations; (n−1) + (n−2) + … + 0 = n(n−1)/2.
  • count_halving(n) = ⌊log₂ n⌋ for n ≥ 1. If 2ᵏ ≤ n < 2^(k+1) then k halvings bring n to 1 and not before. In Python n.bit_length() - 1; in Java 31 - Integer.numberOfLeadingZeros(n). Avoid math.log2/Math.log: floating point can round a boundary such as 2^k − 1 the wrong way.
  • count_triple(n) = n(n+1)(n+2)/6, the number of triples i ≤ j ≤ k < n (that is C(n+2, 3)). Summing over i: for each (i, j) the innermost loop runs n − j times; the pair count with a given i is Σⱼ₌ᵢⁿ⁻¹ (n − j) = T(n − i) with T(m) = m(m+1)/2, and Σₘ₌₁ⁿ m(m+1)/2 = n(n+1)(n+2)/6. Check n = 3: 10.
  • Java: use long. n * (n - 1) is computed in int and overflows for n = 1,000,000 unless you cast first: (long) n * (n - 1) / 2.

Exercise 9 — has_duplicate in read/py/ex_read.py / hasDuplicate in read/java/ExRead.java.

Solution

The error: the claim counts the visible loop and forgets the hidden one. x in seen on a list scans the list, comparing with each stored item until it finds x, so every test costs up to len(seen) comparisons. On n distinct items the i-th test makes i − 1 comparisons, in total 0 + 1 + … + (n − 1) = n(n − 1)/2: Θ(n²) in the worst case (the same count as the all-pairs version; the test in solutions/ confirms exactly n(n−1)/2 comparisons). Best case O(1): a duplicate among the first two items. Java: ArrayList.contains scans using equals, same analysis. Fix: seen = set() (Java HashSet<T>): membership and insertion are O(1) expected, so the function is O(n) expected. The claim "exactly like the set-based version" was the giveaway: it is not, and the only difference is the type of seen.

Exercise 10 — reversed_copy in read/py/ex_read.py / reversedCopy in read/java/ExRead.java.

Solution

The error: list.insert(0, x) is not constant time. Python lists (and ArrayList) store their elements in one contiguous array; inserting at the front moves every element already stored one place to the right (the ArrayList.add(index, e) documentation says so explicitly). When the i-th element is inserted there are i − 1 elements to move, in total n(n − 1)/2 moves: Θ(n²). The doubling test exposes it: ten times more input is about a hundred times more work. Fix: list(reversed(items)), or append everything and reverse once (O(n)); if you really need cheap insertion at the front use collections.deque.appendleft (Java: ArrayDeque.addFirst), O(1) each. Note what the claim got right: the result is correct and "one loop" is true; the claim was wrong because the body of that loop is not O(1).

§4Working with AI

When an AI writes a data structure or an algorithm it often also writes a complexity claim. Treat the claim as a hypothesis and test it:

  1. Hunt for hidden loops. Python: in on a list, list.insert(0, x), list.remove, list.index, s += t in a loop, slicing a long list. Java: ArrayList.contains, add(0, x), remove(Object), String += in a loop. A claimed "one loop" is O(n) only if every statement in it is O(1).
  2. Count, do not time. Wrap the items in a class whose __eq__ / equals counts calls (see solutions/py/test_ex_read.py, solutions/java/ExReadTest.java) and compare the count with the claimed formula for several n.
  3. Run the doubling test. Measure the count (or the best-of-several time, warmed up) at n, 2n, 4n: ratios near 2 mean linear, near 4 quadratic, near 1 constant or logarithmic.
  4. Ask for the invariant, then check it. Ask the AI to state the loop invariant, and put it in the code as a check that runs every iteration (a hook, an assert) before trusting the loop; Exercise 8 is a model.
  5. Ask for witnesses. "Give me c and n₀ for your Big-O claim" and check the inequality yourself: a claim without a witness is not a proof.
